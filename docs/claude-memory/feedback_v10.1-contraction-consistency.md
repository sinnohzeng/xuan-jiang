# v10.1 机械层收缩与文档—脚本一致契约

> 记录时间：2026-08-04。适用范围：writing-polish 全体裁全模式。

## 核心判断

1. **脚本硬红线只保留无歧义集，语境判断交 reviewer**。v9.2 独立评估精确率约 18%：硬红线混入公文合法词（切实推动/提质增效/深度融合/打造/助力/多维度/体系化/重塑）与国标合法标点（破折号，GB/T 15834），无语境豁免即 FAIL 是误伤源。本轮 CN_HARD 15→7 词，降级项转软 WARN 并逐条注明降级理由（anchors §2.0）。
2. **词表必须有唯一权威源 + 机械校验**。同一黑词清单曾在 scan 脚本 / anchors / SKILL.md / reviewer 四处手写，交集仅 5 词。v10.1 起 anchors §1.1 是唯一 SSOT，其余文件只放指针；`scripts/check-rule-consistency.sh` 逐字比对文档与脚本词面，漂移即 exit 1。契约出处：KKKKhazix/human-writing（GitHub，MIT）references/revision.md「检查脚本里的硬禁词必须与判据文件完全一致，增删同轮双向修改」。
3. **机械计数只报不令改（防 Goodhart）**。密度阈值保留计数但 WARN 措辞标注「密度提示，不作改稿目标」：SKILL.md 铁律已证明机械计数曾诱导反向改坏文风。同理删除 fix_word 逐词替换建议表（references/failure-cases.md 案例 1 已证伪机械近义词替换）。
4. **吸收外部技能的三层过滤**：机制可移植（材料门槛量化、七遍改稿顺序）才吸收；词表须体裁门控（外部黑词清单不直接进本技能词表）；硬禁令须过白熊效应审查（「禁止 X」可能反向诱导 X）。形状检测族脚本（比喻聚类/段首重复/短句排队）一律不吸收，形状判断交 reviewer。
5. **踩坑警示**：①插件缓存按 `sort -V | tail -1` 选版本，改版本号即静默升级，版本触点必须 grep 复核；②下游仓（cicpa）GLOSSARY 锁定的白名单词与本技能词表是词表级耦合，重组词表前先 grep 下游锁定词确认不丢（本轮核实「开箱即用」仅存于下游，本仓无耦合）。
