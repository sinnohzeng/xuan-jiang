# v10.0 站位四问前置与场景包

> 记录时间：2026-08-03。适用范围：writing-polish 全体裁全模式。

## 核心判断

1. **政治站位检查是第一环节，不是润色中的一个焦点**。任何写作或润色之前必须先核实：读者是谁、我是谁、经由什么媒介接收（会场口播 / 纸面印发 / 屏幕扫读 / 微信即时通讯 / 机器解析）、有无第二受众（讲话稿的印发读者、抄送范围）。口吻判断错了，后面所有焦点都在错误的基准上优化。方法论出处：任仲然《怎样写作》第七讲受众三问（“一要明白谁要讲话，二要明白在什么场合对什么人讲话，三要明白印发下去的讲话给谁看”）。
2. **读者谱系必须覆盖非工作场景**。早期矩阵只有工作关系五行，写给家人、朋友、自媒体读者、软件系统的稿子没有判依据，默认落进商务客服腔。熟人场景的风险方向与工作场景相反：防过度客气、过度正式，且“过于正式”只提示不阻断。
3. **高政治敏感体裁需要听众反应预演**。党课 / 领导讲话（G2）逐句问“台下的人听了会怎么想、会不会多想”，判据来自一篇央企党课的实战蒸馏（站位 / 语气 / 分寸 / 语境四组铁律）。配套硬闸门：集成审读意见前逐条溯源稿件血统，命中领导审定文字的意见一律不采。
4. **场景细则用 progressive disclosure 下沉**。站位矩阵只加一行，完整操作细则放 `references/scenarios/` 场景包，命中场景才加载。新增场景即新增一个文件并在矩阵加一行。
5. **新检查项同批建假阳清单**（沿用 v9.3.1 教训）：听众预演不适用 G6 / G7 私人写作；熟人场景报“过于正式”只提示不阻断。焦点越靠前，误伤代价越大。
