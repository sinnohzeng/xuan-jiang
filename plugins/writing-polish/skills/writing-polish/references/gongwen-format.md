## 二、正文格式

- **字体**：仿宋
- **字号**：三号（16pt）
- **加粗**：否
- **首行缩进**：2 字符（= 32pt，即 2 × 16pt）
- **行距**：28 磅（固定值）
- **对齐**：两端对齐

## 三、标题层级（排版）

> ⚠️ 本节只管**排版**（编号、字体、字号、缩进）。标题**措辞**的规范在第九节——两者是两回事。排版全对而措辞不对仗、带口语、自曝辩解性质的标题，本节一条都拦不住。

| 层级 | 字体 | 字号 | 加粗 | 编号格式 | 示例 |
|------|------|------|------|---------|------|
| 文件标题 | 方正小标宋简体（未安装时用宋体）| 二号（22pt）| 否 | — | 居中排列 |
| 一级标题 | 黑体 | 三号（16pt）| 否 | 一、二、三、 | 一、总体要求 |
| 二级标题 | 楷体 | 三号（16pt）| 否 | （一）（二）（三）| （一）指导思想 |
| 三级标题 | 仿宋 | 三号（16pt）| **是** | 1. 2. 3. | 1. 加强组织领导 |
| 四级标题 | 仿宋 | 三号（16pt）| 否 | （1）（2）（3）| （1）明确责任分工 |

### 编号规则

- **不使用 Word 自动编号/列表功能**，直接用普通文本写编号
- 一级标题编号后用顿号“、”：一、
- 二级标题编号用中文圆括号：（一）
- 三级标题编号后用下脚点“.”：1.
- 四级标题编号用中文圆括号：（1）

### 标题排列

- 文件标题：居中，可分一行或多行排列，回行时词意完整
- 一级标题：左起顶格，单独占行，标题后不加标点（除问号、省略号外）
- 二级标题：左空二字，单独占行或与正文接排
- 三级标题：左空二字，与正文接排或单独占行
- 四级标题：左空二字，与正文接排

## 四、页码

- **字体**：宋体
- **字号**：四号（14pt）
- **格式**：`-1-`（阿拉伯数字外加一字线）
- **位置**：页面底端外侧（奇数页右侧，偶数页左侧；单面印刷时居中亦可）

## 五、python-docx 实现代码

### 5.1 页面设置

```python
from docx import Document
from docx.shared import Mm, Pt
from docx.enum.text import WD_ALIGN_PARAGRAPH
from docx.oxml.ns import qn

doc = Document()
section = doc.sections[0]
section.page_width = Mm(210)
section.page_height = Mm(297)
section.top_margin = Mm(37)
section.bottom_margin = Mm(35)
section.left_margin = Mm(28)
section.right_margin = Mm(26)
```

### 5.2 设置中文字体的辅助函数

```python
def set_run_font(run, font_name, size_pt, bold=False):
    """设置 Run 的中文和西文字体。"""
    run.font.name = font_name
    run.font.size = Pt(size_pt)
    run.bold = bold
    # 关键：必须同时设置 w:eastAsia 属性，否则中文字体不生效
    r_elem = run._element
    rPr = r_elem.get_or_add_rPr()
    rFonts = rPr.get_or_add_rFonts()
    rFonts.set(qn('w:eastAsia'), font_name)
```

### 5.3 正文段落

```python
def add_body_paragraph(doc, text):
    """添加公文正文段落：仿宋三号，首行缩进2字符，行距28磅。"""
    para = doc.add_paragraph()
    para.paragraph_format.first_line_indent = Pt(32)  # 2字符 = 2 × 16pt
    para.paragraph_format.line_spacing = Pt(28)
    para.paragraph_format.alignment = WD_ALIGN_PARAGRAPH.JUSTIFY
    run = para.add_run(text)
    set_run_font(run, "仿宋", 16)
    return para
```

### 5.4 各级标题

```python
def add_doc_title(doc, text):
    """文件标题：方正小标宋简体（或宋体）二号，居中。"""
    para = doc.add_paragraph()
    para.paragraph_format.alignment = WD_ALIGN_PARAGRAPH.CENTER
    para.paragraph_format.line_spacing = Pt(28)
    run = para.add_run(text)
    # 方正小标宋简体系统可能未安装，用宋体作为备选
    try:
        set_run_font(run, "方正小标宋简体", 22)
    except Exception:
        set_run_font(run, "宋体", 22)
    return para

def add_heading_level1(doc, number, text):
    """一级标题：黑体三号，顶格。如 add_heading_level1(doc, '一', '总体要求')"""
    para = doc.add_paragraph()
    para.paragraph_format.line_spacing = Pt(28)
    run = para.add_run(f"{number}、{text}")
    set_run_font(run, "黑体", 16)
    return para

def add_heading_level2(doc, number, text):
    """二级标题：楷体三号，左空二字。如 add_heading_level2(doc, '一', '指导思想')"""
    para = doc.add_paragraph()
    para.paragraph_format.first_line_indent = Pt(32)
    para.paragraph_format.line_spacing = Pt(28)
    run = para.add_run(f"（{number}）{text}")
    set_run_font(run, "楷体", 16)
    return para

def add_heading_level3(doc, number, text):
    """三级标题：仿宋三号加粗，左空二字。如 add_heading_level3(doc, 1, '加强组织领导')"""
    para = doc.add_paragraph()
    para.paragraph_format.first_line_indent = Pt(32)
    para.paragraph_format.line_spacing = Pt(28)
    run = para.add_run(f"{number}. {text}")
    set_run_font(run, "仿宋", 16, bold=True)
    return para

def add_heading_level4(doc, number, text):
    """四级标题：仿宋三号，左空二字。如 add_heading_level4(doc, 1, '明确责任分工')"""
    para = doc.add_paragraph()
    para.paragraph_format.first_line_indent = Pt(32)
    para.paragraph_format.line_spacing = Pt(28)
    run = para.add_run(f"（{number}）{text}")
    set_run_font(run, "仿宋", 16)
    return para
```

### 5.5 页码

```python
from docx.oxml import OxmlElement

def add_page_number(doc):
    """添加页码：宋体四号，居中，格式 -1-。"""
    section = doc.sections[0]
    footer = section.footer
    footer.is_linked_to_previous = False
    para = footer.paragraphs[0]
    para.alignment = WD_ALIGN_PARAGRAPH.CENTER

    # 前缀 "-"
    run_prefix = para.add_run("-")
    set_run_font(run_prefix, "宋体", 14)

    # 页码域代码
    fldChar_begin = OxmlElement('w:fldChar')
    fldChar_begin.set(qn('w:fldCharType'), 'begin')
    run_field = para.add_run()
    run_field._element.append(fldChar_begin)

    instrText = OxmlElement('w:instrText')
    instrText.set(qn('xml:space'), 'preserve')
    instrText.text = ' PAGE '
    run_instr = para.add_run()
    run_instr._element.append(instrText)

    fldChar_end = OxmlElement('w:fldChar')
    fldChar_end.set(qn('w:fldCharType'), 'end')
    run_end = para.add_run()
    run_end._element.append(fldChar_end)

    # 后缀 "-"
    run_suffix = para.add_run("-")
    set_run_font(run_suffix, "宋体", 14)
```

## 七、日期时间写法规范

公文中的时间节点必须具体明确，避免模糊表述。

| 正确写法 | 错误写法 | 说明 |
|---------|---------|------|
| 2024 年 6 月 30 日前 | 6 月底前 | 时间要具体到日 |
| 2024 年 12 月 31 日前完成 | 年底前完成 | 避免“年底”“月底”等模糊表述 |
| 自 2024 年 1 月 1 日起施行 | 自发布之日起施行 | 尽量明确具体日期 |
| 每季度末月 15 日前报送 | 按时报送 | 涉及周期性要求时写明具体日期 |

**原书依据**：会议纪要中，会上领导说的“6月底、4月底”，纪要应当细化到“6月30日前”“4月30日前”，有利于避免因时间要求模糊影响贯彻落实。

## 八、数字使用规范

### 使用中文数字的场合

- 公文标题层级编号：一、二、三，（一）（二）（三）
- 成语和惯用语：三令五申、五湖四海、三个吃透
- 概数和约数：几十个、三五天、七八成
- 星期：星期一、星期五

### 使用阿拉伯数字的场合

- 统计数据和精确数值：530 万亩、27.2%、3.5 亿元
- 公历日期：2024 年 3 月 16 日
- 时间：14:30
- 编号和序号：第 1 批、第 2 条
- 千分位使用英文逗号：1,000,000

### 混合使用原则

- 同一段落中，同类数字的写法应保持一致
- 当中文数字和阿拉伯数字混排时，以所在语境为准
- 标题层级用中文数字，正文中的统计数据用阿拉伯数字

## 九、标题语体规范（v9.3 新增，管措辞不管排版）

> 与第三节的分工：**三节管排版，本节管措辞**。本节由 clean-context reviewer 判定，脚本抓不到（标题里每个字都是正常汉字）。
>
> 沉淀来源：2026-07-28 中注协工作秘密上云附件实战，用户原话「各个章节的标题，请你参考党政公文语言风格重写一下。目前太长了，风格不对。」

### 9.1 一级标题（一、二、三）

| 规则 | 说明 |
|---|---|
| **名词短语，2 至 6 字为宜** | 「一、总体结论」「三、制度依据」。动宾结构、完整句一律不用 |
| **同级对仗** | 同一篇里各一级标题字数、结构接近。出现 2 字与 12 字混排 = 要改 |
| **禁冒号** | 「三、制度依据：从保密法到 14 号文」→「三、制度依据」 |
| **禁疑问句式** | 「四、能不能上政务云」→「四、承载平台」 |
| **禁悬垂「的」字尾** | 「五、可以参照的实践」→「五、实践依据」 |
| **禁「……的理解」「……的说明」类后缀** | 自曝辩解性质：读者看到目录上有一节专叫「某文件某部分的理解」，第一反应是「这一段肯定对我们不利」。改为内容本身的名词式，如「……的适用范围」 |
| **禁「之一 / 之二」编号补丁** | 分不开就是分类维度选错了，回去重切 |
| **禁把文号写进标题** | 文号进正文首句。标题带文号必然超长且雷同 |
| **禁行业白话** | 「上云」「打通」「赋能」进标题即失格。「二、上云范围」→「二、迁移范围」 |
| **禁技术词当标题** | 领导未必秒懂的词（承载、链路、纳管）换成业务语 |
| **禁泄露我方工作过程** | 「现场备问」「答辩预案」「补充调研发现」是我方内部工作阶段名，读者不该看到。「现场备问」→「常见问答」 |
| **标题要点出要害** | 一节真正要说的是「名单不等于政务云名单」，标题却叫「评估名单的收录范围」，等于把最该注意的话藏起来。标题应当承载判断 |

**同级动词必须同构**：「（一）由服务商落实 /（二）由云平台带来 /（三）由中注协承担」——落实、带来、承担三个动词不同构，「带来」尤其口语。改为「（一）服务商责任 /（二）平台责任 /（三）协会责任」。

**同级分类维度必须唯一**：「（一）司法部（二）评价中心（三）中评协（四）其他机构（五）私有云路线」——前四按机构切，第五突然按技术路线切，同一家单位可以同时落进（四）和（五）。要么全按机构，要么全按部署形态，不能混。

**目录自检法**：把所有标题抽出来单独排成一列通读。读起来不像一份东西的目录 = 要改。

### 9.2 run-in 小标题（`**XXX。**` 后接正文）

**它是标题，不是句子。** 规范：名词性短语，2 至 12 字，无谓语构成的完整判断，无疑问，无口语。

| 病 | 正 | 病因 |
|---|---|---|
| **谁评。** | **评估主体。** | 口语设问 |
| **怎么评。** | **评估流程。** | 口语设问 |
| **评完管多久。** | **有效期与持续监督。** | 口语设问 |
| **名单本身写着政务云。** | **公告名单所载的平台名称。** | 论证旁白 |
| **政府采购文件里也这么叫。** | **政府采购文件中的称谓。** | 论证旁白 |
| **司法部的政务云是租的，不是自建的。** | **司法部政务云的取得方式。** | 完整判断句 |
| **这套系统装的信息与中注协基本相同。** | **该系统承载的信息。** | 完整判断句 + 口语「装」 |
| **法律和行政法规怎么规定工作秘密。** | **法律和行政法规的规定。** | 口语设问 |

**三条判据**：
1. 有谓语动词构成完整判断？→ 它是句子不是标题。
2. 是疑问？→ 换成对应的名词（谁评 → 评估主体）。
3. 它说的是「这一段讲什么」还是「这一段的结论是什么」？说结论 → 结论移到正文首句，标题只留事项名。

**同级对仗**：同一节下 run-in 标题字数结构要接近。一组里出现 2 字（「隔离。」）与 10 字（「机房物理安全与设施境内。」）混排 = 要改。

**粗体范围**：粗体只包事项名，句号在粗体内、后续正文在粗体外。`**迁移前保密审查。** 这是上云新增的唯一一项。`——不要把整句判断都加粗。

### 9.3 章序

章与章之间同类项要相邻。「三、制度依据 → 四、承载平台 → 五、实践依据」把两个「依据」用一个不同类的章隔断，目录上三行读起来就不对。同类相邻，或把中间那章降为子目。

## 十、开篇帽子范式（v9.3.1 新增，定式不得拆）

> 沉淀来源：2026-07-28 中注协实战。审稿人把帽子里的目的排比判成「作者以客户本位立言、站位越界」，主对话据此把帽子改掉，被用户当场驳回：「你党政公文的帽子部分别反复啊……这个帽子没必要变呀，党政公文的帽子部分，用好写作技能。」

### 10.1 标准几何

**「为〔目的状语排比，由近到远／由小到大〕＋〔根据 X 依据〕＋〔结合 Y 实际〕＋ 制定／提出本 Z。」**

目的前置、排比落点、动词收口。三段缺一不可，顺序不得调换。

锚本：

> 为加强和改进党员教育培训工作，锻造过硬党员队伍，不断增强党的创造力、凝聚力、战斗力，根据《中国共产党章程》……，制定本规划。
> ——《全国党员教育培训工作规划（2024-2028）》

> 为深入贯彻落实……决策部署，规范和引导……，提升政务数字化智能化治理和服务水平，制定本指引。
> ——《政务领域人工智能大模型部署应用指引》

### 10.2 第三方咨询机构的改造（截断重接）

咨询机构不是发文机关，**严禁**照搬「制定本规划／提出本意见」这类落款式收口（属自发规范、请示稿语气）。**保留前半的目的排比，只换后半的落点**：

> 为〔顺应新形势／落实部署〕，〔推进 X〕、〔提升 Y〕，某某单位委托某某公司开展咨询论证〔，就 Z 提出建议〕。

附件、说明类短文的落点换成「现将有关问题说明如下」。

### 10.3 帽子的三条禁令

1. **禁拆目的排比**。排比是帽子的骨架，压成单一目的（「为说明……」）等于把公文体降成事务性便条。
2. **禁在排比中间插入委托关系**。「为说明 A，受某某委托，根据……」把气口打断。委托关系要么进后半落点，要么不写。
3. **禁落款式收口**（咨询体裁）。`grep -nE "制定本(规划|方案|报告|意见|指引)"` 正文应零命中。

### 10.4 ⚠️ 口吻审查在帽子上的已知假阳

**「为……推进某某单位某某工作」这个目的状语，不是作者以客户本位立言，不是站位越界。** 它是公文帽子的固定成分，功能是交代成文缘由，与「谁在说话」无关。

reviewer 若把帽子里的目的排比报为「协会本位口吻」「我方以此口吻立言略越位」，**主对话应判为假阳并驳回，不得据此改写帽子**。

同理属假阳的还有：帽子里的「根据《X 法》《Y 规定》」被报为「堆砌文号」（依据段是帽子必备成分，非堆砌）；「结合本单位实际」被报为「替客户判断」（这是成文依据的常规表述）。

**边界**：帽子之外的正文若出现同型祈使或替客户拍板，仍按 [`stance-and-register.md`](stance-and-register.md) §2 处理。假阳豁免只覆盖帽子本身。
