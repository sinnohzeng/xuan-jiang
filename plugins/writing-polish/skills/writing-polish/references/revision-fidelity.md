# 改稿忠实性（Polish step 3 前置铁律）v9.6

> **v9.6 新增，来自 2026-07-28 实战失误。** 一轮以「去 AI 味、改口吻」为目的的润色，改出了三处比 AI 味严重得多的错误：改动了引文的情态、新增了原稿没有的事实、把一条法规义务安在了不适用的主体上。三处全部通过了 L1 脚本，也全部通过了主对话自审，是 clean-context reviewer 逐字对原文才抓出来的。
>
> **核心认知**：润色的操作对象是**表达**，不是**内容**。一旦改到内容，润色就变成了篡改，而篡改在公文、法律、审计、咨询这些体裁里是致命的——AI 味最多让人觉得稿子不好，改错引文会让整份材料作废。
>
> 适用：全体裁，**G1 公文 / G3 报告 / G4 学术 / G8 法律类必查**。

## §1 三条铁律

### 铁律一 · 引文的情态不得改动

转述、概括、归纳引文时，**情态动词与语气必须逐字对应原文**。情态是法条的效力等级，改一个字就是改一档效力。

| 原文 | 错误转述 | 为什么致命 |
|---|---|---|
| 应在确保安全的前提下**再考虑**向云计算平台迁移 | 先确保安全，**再推进**迁移 | 「考虑」是留有余地，「推进」是既定动作。原文没许可迁移，转述许可了 |
| **可以**依法采取 | **应当**依法采取 | 授权变义务 |
| **原则上**不得 | **不得** | 例外空间被抹掉 |
| **鼓励**优先采购 | **要求**优先采购 | 倡导变强制 |
| 加强对……的**管理** | 对……作出**限制** | 管理不等于限制 |

**中文常见情态梯度**（从弱到强，跨档即为改意）：
可以／鼓励／倡导 ＜ 宜／原则上 ＜ 应当／须 ＜ 必须／严禁／不得

**动作梯度同理**：了解 ＜ 研究 ＜ 考虑 ＜ 规划 ＜ 推进 ＜ 实施 ＜ 完成

**自查动作**：凡 `>` 引文块后两行内出现转述句，把转述句的谓语和情态词逐个拎出来，回到引文里找对应词。找不到一模一样的词，就是改意。

**唯一安全的写法**：转述时保留原文的关键词。上例的正确改法是「该句设定的是以确保安全为前提」——只归纳句子的功能，不替原文把「考虑」升格成「推进」。

### 铁律二 · 润色不得新增原稿没有的事实

润色可以删、可以换词、可以调序、可以合并，**唯独不能让原稿里没有的事实断言凭空出现**。

最危险的是「读起来更完整、更有力」的那一类补写，因为它正好命中润色的动机：

| 原稿事实 | 润色时长出来的 | 为什么是编造 |
|---|---|---|
| 三家单位的同类业务在云上运行 | 三家单位的同类业务**均已由自建机房转为**云上承载 | 调研拿到的是**当前部署形态**，不是**迁移历史**。「由 A 转为 B」是一条新的因果与时序断言，没有来源 |
| 该中心所用平台在名单内 | 该中心**选用该平台的考虑有两点**：…… | 「考虑」是对方的内部动机，我方代述，对方一开口就穿帮 |
| 该会与本单位同受某部监管 | 两者**法律地位相近** | 法律定性，原稿没有，也没人有资格下 |
| 名单共 88 条，含政务云字样 32 条 | 名单**里有 32 条直接写着**政务云 | 事实没错，但「直接写着」是新增的强调语气（见 §2） |

**新增事实的四种伪装**：
1. **时序**：「已」「仍」「原本」「此前」「转为」「延续」
2. **因果**：「因此」「由于」「基于……考虑」「出于」
3. **动机**：「旨在」「考虑到」「为了」（用在第三方身上时）
4. **定性**：「属于」「相当于」「相近」「一致」（法律、资质、性质类判断）

**自查动作**：逐句问「这个词对应原稿的哪一句、哪一份材料？」答不上来就删回去。**改稿人没有取证权。**

### 铁律三 · 引条款须核对义务主体

引用一款规定给某个主体派活之前，先确认**该款的义务主体确实是这个主体**。

实例：某实施条例第七十三条两款，第一款「**中央国家机关**应当结合工作实际制定本行业、本领域工作秘密事项具体范围」，第二款「**机关、单位**应当加强本机关、本单位工作秘密管理」。给一家社会团体写工作任务时引第一款，等于默认该团体承担中央国家机关的义务——懂行的读者一眼看穿，且这个默认往往正是全篇有意绕开的争点。

**自查动作**：条文分款的，逐款读主语。主语对不上，换条款或换依据，**不要用「参照执行」把主体问题糊过去**——「参照」本身就是替读者做了适用性认定（见 [`stance-and-register.md`](stance-and-register.md) §2）。

## §2 强调语气也是内容

改稿人最容易给自己开的口子是「我只是让它更有力一点」。加在事实上的强调副词，是新增的态度断言：

| 加了什么 | 读者收到的额外信息 |
|---|---|
| **直接**写着 / **白纸黑字** | 你看，我说的没错吧（自证清白，见 stance-and-register §4） |
| **确已** / **完全** / **根本** | 作者在防一个没人提出的质疑 |
| **同一份**文件（第三次说） | 作者对这份证据不自信，靠重复壮胆 |
| **全部**规定 / **唯一**依据 | 一条反例就翻盘的绝对化断言 |

**判据**：删掉这个副词，事实是否照样成立？照样成立就删。

## §3 与其他焦点冲突时的排序

润色过程中，忠实性与其他焦点冲突，**忠实性优先**：

```
引文/事实忠实性  ＞  客户明示的骨架与结论  ＞  口吻与站位  ＞  语体一致  ＞  AI 味
```

两条推论：

**推论一**：为了让口吻更谦抑而弱化引文的效力，或者为了让句子更顺而替第三方补动机，**都是拿忠实性换文采，一律不做**。

**推论二**：**用户/客户当场拍定的结论句、骨架、章序，不因口吻焦点而改。** 详见 [`stance-and-register.md`](stance-and-register.md) §2.0 假阳清单末条。

## §4 Polish step 3 的执行位置

`SKILL.md` §2.2 step 3 的有序 sweep 之前，**先跑本文的三条自查**：

```
step 3.0（本文）忠实性自查 —— 引文情态 / 新增事实 / 条款主体
  ↓ 通过后才进
step 3.2 有序单维 sweep —— ①口吻站位 → ②达意立意 → …… → ⑥翻译腔
```

**顺序理由**：sweep 的每一维都在改字，改完再回头核忠实性，要比对的 diff 已经堆了一层。忠实性问题只能对着**原稿**查，不能对着**改后稿**查。

**reviewer 侧**：`agents/writing-reviewer.md` 的「材料·事实」焦点已含本文三条，reviewer 若同时拿到原稿与改后稿，须逐条比对；只拿到改后稿时，须把无法核实来源的事实断言列入「需追问」，不得默认为真。
