## §0 核心机制

AI 味不是单点 bug，是**多层叠加**：

1. **训练目标**：RLHF 推向高通过率的"标准答案机"
2. **解码策略**：token 概率最高 = 最像好答案的句子，不是某个真人会写的句子
3. **训练数据同质化**：互联网被 AI 反向污染，模型学到上一代模型的模板
4. **统计性思维替代语言思维**：人是先有想法再找词；AI 预测下一个最可能的词
5. **戏剧化偏好**：AI 受产品文案、自媒体爆款标题污染，倾向动作化、战斗化、夸张化词汇

> **v9.0 白熊效应治理**：大幅精简词表（230→80 条），删除英文词汇红线（中文场景几乎不出现）、低频近义变体（只保留核心词根）、已被 LLM 自改进覆盖的词。硬红线只保留确凿 AI 指纹，软信号下沉 reviewer 做语义判断。

**真正"去 AI 味"的核心不是改词，是把表达从「标准答案」拉回「具体表达」**：

- 留**犹豫**——不强求圆满
- 留**偏执**——不假装平衡
- 留**具体**——不滑向抽象
- 留**人称**（我、他、张三）——不藏在"研究表明"后面
- **长短句交错**，允许局部失衡
- 该用**数字**时用数字（"60%" 而不是"大幅提升"）
- 该**点名**时点名（"敦煌研究院项祖怡 1985 年" 而不是"有学者"）

## §1 硬红线

> 出现即扣分。改完必须 scan 验证全部 = 0。scan-ai-taste.sh regex 硬扫这些条目。

### §1.1 核心公文黑词（15 条）

每条都有同义词替代，但首选**直接删**。这些词出现 = 内容缺乏具体性。

1. **赋能**
2. **重塑**
3. **深度融合**
4. **闭环**
5. **抓手**（指代抽象时）
6. **链路**
7. **打造**
8. **助力**
9. **切实推动**
10. **多维度**
11. **体系化**
12. **话语建构**
13. **跨界融合**
14. **提质增效**
15. **拉通**

**为什么是 AI 味**：互联网被这些词反向污染，AI 在公文场景反射性输出。它们是抽象大词，不指向任何具体动作。

### §1.2 元注释 / 客服话术（19 条）

RLHF 安全训练让 AI 在回答前后加大量元注释、自我介绍、免责声明、服务话术。这些是确凿的 AI 客服腔指纹。

#### 元注释开头（5 条）

16. **以下是几点说明** / 以下是几点想法 / 下面给出
17. **我将从 X 个方面来回答** / 我将围绕 X 个维度展开
18. **让我为您整理一下** / 让我帮您梳理 / 让我先来分析
19. **请允许我** / 请容我先 / 在此我想
20. **接下来我会** / 我接下来要 / 下一步我将

#### 自我介绍 / 身份声明（4 条）

21. **作为一个 AI 助手** / 作为一个 AI 模型 / 作为一个语言模型
22. **作为大语言模型** / 作为对话式 AI
23. **我虽然是 AI，但** / 我作为 AI 的局限性是
24. **我没有 X 能力** / 我无法 X / 我不能为您 X

#### 免责声明（5 条）

25. **以上信息仅供参考** / 仅供参考请以官方为准
26. **具体情况建议咨询专业人士** / 建议咨询医生 / 建议咨询律师
27. **我不能提供 X 建议，但可以**
28. **请注意** / 请知悉（孤立成段，无具体内容）
29. **以上内容如有错误请指正** / 如有不当之处请见谅

#### 服务话术段尾（5 条）

30. **希望对您有帮助** / 希望这能帮到您
31. **如有其他问题，欢迎继续提问** / 随时找我
32. **有任何疑问请随时告诉我**
33. **祝您 X 顺利**（除非确实是结尾问候场合）
34. **谢谢您的提问** / 谢谢您的信任 / 感谢您的耐心

**改写**：删除元注释，直接进入正文，由读者自行判断。

### §1.3 工具残留（6 条）

正式文档严禁出现以下字符串，是确凿的 AI 工具输出 bug：

35. `oaicite` / `contentReference` / `oai_citation`
36. `attached_file`
37. `grok_card` / `grok-card`
38. `+1`（紧跟在引用后做"赞同"标记）
39. `[\d+]` 紧贴中文末尾（机械引用编号）
40. Placeholder dates：`2025-xx-xx` / `XXXX-XX-XX` / `{{access-date|...}}` / `[date]` / `[year]` / `[month]`

**改写**：清理所有工具残留标记，改成正常引用脚注；占位符要么填实际日期，要么删除该字段。

### §1.4 标点硬规范（7 项）

41. **— 破折号 / —— 中文长破折号**（英文 em-dash 同样是头号 AI 指纹）
42. **括号内插入式补充**：`（如...）`、`（即...）`、`（也就是说...）`——只检测这三种 AI 起手式叙事补充

   **合规括号 7 类白名单**（scan 不扩展检测，仅作认知层指引）：
   1. 法条文号引用：（国发〔2022〕14号）
   2. 法律施行日期
   3. 标准缩写首释：（OA）、（CMS）、（AICPA）
   4. 表格数据备注
   5. 图表标题内嵌
   6. 计算说明
   7. 章节自引：（详见 §X.Y）

43. **中文引号必须用大陆国标弯引号 " " 和 ' '**（GB/T 15834-2011）：严禁中文上下文用 ASCII 直引号 `"` `'` 或直角引号 `「」` `『』`。纯英文短语 / 代码 / 技术术语保留 ASCII。
44. **数学符号代替自然语言**：`+` `=` `→` `&` 在正式中文叙述里禁用。**严禁机械替换**为"和""与""即"，应重构整段表述。
45. **每段加粗冒号开头**：`**重点：**xxx`、`**关键：**xxx` 等 ChatGPT 输出 layout 反射弧。
46. **半中半英术语**：`操作 checklist`、`前端 dev`、`prompt 工程` 等中英缝合词。已有标准译名必须用中文。
47. **英文标点穿插中文段落**：中文段落里残留英文逗号 `,` 句号 `.` 冒号 `:` 分号 `;`。

## §2 软信号

> 保留描述但不做 regex 硬扫。出现 1-2 处可接受，密集出现须改写。由 reviewer NL 判断。

### §2.1 翻译腔词汇（10 条）

- **在某种意义上说**
- **在...的背景下** / 在...的语境下
- **在当今...的时代** / **随着...的发展**
- **不可磨灭的**（影响 / 印记）
- **可谓是** / 堪称
- **与此同时**（每段都来一句）
- **与之相对** / 与此相反
- **不容忽视**
- **从...到...**（虚假范围）
- **值得注意的是** / 值得一提的是

**为什么是 AI 味**：英文学术句式直接翻译过来的中文，真实中文写作不会这么开头。

### §2.2 套话连接词 / 情感空话（15 条）

- **首先...其次...最后...**（三段式套壳）
- **不难发现** / 不难看出
- **综上所述** / 总而言之 / 总的来说
- **由此可见** / 由此观之
- **本质上** / 究其本质
- **更深层次地看**
- **需要指出的是** / 必须强调的是 / 不可否认的是
- **令人印象深刻** / 令人惊叹 / 令人瞩目
- **不可或缺** / **至关重要**（滥用，连鸡毛蒜皮都"至关重要"）
- **独树一帜** / 别具一格
- **大放异彩** / 熠熠生辉 / 璀璨
- **充满活力**（vibrant 直译）/ 蓬勃发展
- **经久不衰**
- **接住** / **托住**（情绪——AI 客服腔标志）/ **共情**（动词滥用）/ **看见你**
- **模糊归因**：业内人士指出 / 相关研究表明 / 大量实践证明 / 有学者认为 / 普遍认为（AI 没有真正的来源，但又要"显得有依据"）

### §2.3 戏剧化隐喻（保留 IT 白名单机制）

正式书面语禁用，但 IT 实物语境（机房 / 等保 / WAF / NGFW）内合法：

- **三件武器** / 杀手锏 / 三层防御 / 多重防御
- **闸门** / 自动闸门 / 兜底闸门
- **战场** / 主战场 / 阵地（除非真的是军事场景）
- **武器化** / 装备化 / 装上 / 加装
- **翻车** / 踩坑 / 跑通 / 走通 / 起飞
- **吐文字** / 吐结果 / 喷出 / 蹦出
- **王炸** / 大招 / 终极武器 / 杀招

### §2.4 大厂黑话（保留党政白名单机制）

- **对标**（党政"对标对表""对标先进"语境合法）
- **对齐颗粒度** / 颗粒度
- **打法** / 玩法
- **沉淀** / 沉淀下来
- **复盘**（非正式分析场景滥用）
- **底层逻辑** / 顶层设计
- **赛道** / 切赛道 / 抢赛道
- **赛马** / 赛马机制
- **跑赢** / 跑赢大盘
- **三件套** / 组合拳 / 铁三角
- **下沉** / 下沉市场
- **生态** / 生态化（除非真在讨论生态系统）
- **抢占心智** / 用户心智

### §2.5 网络口语 / 程序员腔

正式中文书面语禁用：

- **本仓库** / 本号 / 本站（自媒体腔）
- **锚点** / 硬约束 / 硬规则（伪术语化）
- **降智** / 智商税 / 裂开 / 蚌埠住了 / 绝绝子 / YYDS
- **干货** / 满满的干货 / 种草 / 拔草 / 梭哈
- **MVP** / PMF / 冷启动 / 解耦 / 范式（非技术语境滥用）

### §2.6 结构级反模式（reviewer 判定，非 regex）

1. **僵化收尾段** —"综上所述" / "面对未来" 强行升华
2. **"挑战与展望"双段套壳** —"尽管面临...挑战，但..."
3. **每段首句高度同质** — 每段都是"从...角度看""值得思考的是"
4. **段落顺序可换不影响理解**（打乱测试）
5. **过度归纳的导语** —"本文将从 A、B、C 三方面展开"
6. **小标题三段对仗** —"是什么 / 为什么 / 怎么办"机械三段
7. **正能量结尾反射弧** — 任何主题都收在"充满希望" / "未来可期"
8. **话题漂移** — 文章从 X 主题逐段演变到 Y 主题
9. **形容词堆砌** — 连用 3 个以上同义形容词
10. **否定平行结构** —"不是 X，而是 Y"密集出现（段内 ≥3 次才软 WARN）
11. **三连排比** — A、B、C 三段并列形容
12. **段尾分词短语挂总结** —"体现了 X / 反映了 Y / 彰显了 Z"
13. **"问题—原因—对策"机械三段论** — 公文味 + AI 味叠加最严重场景
14. **每个论点配工整三例** — rule of three 滥用
15. **过分平衡的论证** — 任何观点都"一方面...另一方面..."，没有真观点

## §3 咨询报告专属约束

> 第三方咨询机构对甲方的实施方案、调研报告、对照启示等交付物专用，对应锚本 06 与 09 的对照。

1. **身份边界**：禁止「为贯彻落实 X 协会规划」等政治承接句开篇——这是甲方处室文件格式，咨询机构使用即身份越界。直接进入判断。
2. **结论先行 + 证据支撑**：每节首段给出判断，后续用具体单位、平台、数据展开。禁止把判断埋到段尾"综上所述"。
3. **不为特定厂商背书**：用功能描述，不指名厂商。
4. **「其一 / 其二 / 其三」仅限请示事项段**：非请示段用「一是 / 二是 / 三是」。
5. **多方利益话题先静默**：涉及跨主体收益重分配 / 跨地区数据主权的话题，保持现状描述层面。

## §4 机器指纹

> 前几节治的是"词不对"。本节治的是**词都对、句都通，但连起来不像人写的**。

### §4.1 符号汉字化（最硬的单条指纹）

**禁止用汉字「加」当连接符**。

- ❌ 概念扩展**加**两层关键词**加**语义加权
- ✅ 概念扩展、两层关键词和语义加权

### §4.2 连接词单一化

AI 中文并列连词坍缩到只剩「与」和顿号。真人混用：和、跟、以及、还有、并、等。

**自查**：全文 `与` 远大于 `和` 加 `以及` 之和，命中；列举句结尾一次「等」都没有，命中。

### §4.3 自造隐喻名词系统

把流程物化成私人词汇：**硬门、闸、档、口径、底座、真源、走脚本、落成、回流、打通**。

**判别**：如果一个词需要你在括号里解释它，它就不该出现在对外文档里。

### §4.4 主张腔

- ❌ **不自研底座。**（无主语否定句独立成段）
- ❌ **只**做叙述合成（连续三个以上的「只」）

全文出现一次是风格，出现三次是腔调。

### §4.5 叙事编排（先立障碍再显功）

- ❌ 针对……的问题，用……解决 ／ 在没有技术团队的情况下……／ 对照外包报价，仅……即……

**为什么是 AI 味**：铺垫困难、设置对照组、解释"为什么难"，是产品文档的本能，不是事务性文档的写法。

### §4.6 压缩洁癖（省量词、省中心语、过度对仗）

- ❌ **6 候选模型**横评（缺量词"个"）／ **8 条对抗**（缺中心语"样本"）
- ❌ 条目标签清一色两两对仗、长度整齐（`产品与工程`／`模型选型`／`对外沉淀`）

真人的标签是参差拖沓的，甚至半句话当标签。**太齐就是机器**。

### §4.7 零缺陷率本身就是破绽

真人写 300 字必有一两处成分残缺、冗余。整篇零病句、零冗余，是最大的机器信号。

**处理原则**：不要为了像人而故意写病句。接受长短句失衡、允许某句稍长稍绕。

### §4.8 精度不一致

同一份文档里 `27339`（精确到个位）和 `约 9 万` 混排。真人的强迫症要么全精确要么全模糊。

## §5 重要保留项（NOT AI 味，应主动使用）

### "一是…二是…三是…" 党政公文标准列举法

**这不是 AI 味，是党政公文的标准结构**，区别于 AI 机械化的"首先...其次...最后"。

- 一级：中文数字"一、二、三"
- 二级：`一是 / 二是` 或 `（一）/（二）`
- 末段请示事项：`其一 / 其二 / 其三`

### 八项文风指纹（正面对齐）

| 编号 | 指纹 | 具体表现 |
|---|---|---|
| 1 | 段落起手用动宾短语或偏正名词短语 | "坚持统筹规划""推进整合" |
| 2 | 句式以长句＋分号为主 | 一段 200—400 字，分号 3—5 个 |
| 3 | 动词偏好收敛 | 推动／推进／加快／加强／完善／健全／落实／统筹 |
| 4 | 判断词带程度软化 | 业已／基本／总体／较为／相对 |
| 5 | 结构引入语规范 | 按照……要求、围绕……、聚焦……、依托…… |
| 6 | 连接词规范 | 同时、此外、在此基础上、进一步 |
| 7 | 数字规范 | 年份精确到月；层级编号用中文数字 |
| 8 | 决策语气软化 | 建议／拟／呈请／审议批准；避免"必须""一定要" |

## §6 量化阈值表

改完必须跑 `bash scripts/scan-ai-taste.sh "$FILE"`，达不到阈值禁止交付。

### 软阈值（密度限制，按文长动态化）

scan-ai-taste.sh 自动按句子数动态调整阈值，直接跑 scan 看 ✓ / ⚠ 即可：

| 文长（句数） | 已经 | 核心 | 这一 |
|---|---|---|---|
| < 200 句（短文） | ≤ 3 | ≤ 3 | ≤ 2 |
| 200-500（中文） | ≤ 6 | ≤ 6 | ≤ 4 |
| 500-1000（长文） | ≤ 9 | ≤ 9 | ≤ 6 |
| ≥ 1000（超长） | ≤ 15 | ≤ 15 | ≤ 10 |

### 句长方差（人写有长短）

句长标准差阈值 ≥ 8，低于此值说明句长过于均匀，AI 味嫌疑。

## §7 使用流程

### 四步闭环

1. **对标阅读**（写作前）：根据文稿类型选择对应锚本通读
2. **对标写作**（写作中）：段首默念锚本句式，判断词默念软化词
3. **扫描自检**（写作后）：`bash scripts/scan-ai-taste.sh "$FILE"`，任何硬约束未达标禁止交付
4. **念改**（交付前）：朗读对照，问"这段话能放进国办文件里吗？"
