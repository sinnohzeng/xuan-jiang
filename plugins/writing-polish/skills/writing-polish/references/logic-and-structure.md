## 一、逻辑审查

### 逻辑主线

任何文稿文章都要有一条贯穿始终的逻辑主线。

> "按照逻辑主线把文字一句一句、一段一段、一页一页码好摆顺，形成重重叠叠顺理成章的关系。特别重要的文字，一个逗号一层意思，一个句号一个观点，均应在逻辑主线的引导掌控之下。"

### 渔网隐喻及其操作转化

老石把写作比作用渔网打鱼，纲粗目细，纲举目张。

**操作化审查要点**：
- **纲是否立得住？** 全文的核心论点和主线是否清晰有力，能否把所有内容收拢？
- **目是否张得开？** 各部分内容是否在主线的引领下有序展开？
- **有没有断了的网线？** 有没有哪个段落或论点与主线脱节，导致论证出现漏洞？如果几个细目的网线断了，纲无论怎么放怎么收都成了徒劳。

### 常见逻辑问题

| 问题 | 表现 | 审查方法 |
|-----|------|---------|
| 概念口径不一致 | 同一事物前后用不同概念指代 | 全文搜索关键概念，确认一致性 |
| 盲目推理判断 | 无依据地得出结论 | 每个结论追溯其前提和依据 |
| 论据证明不了论点 | 事例和观点脱节 | 检查每个论据是否直接支持所在论点 |
| 归纳演绎“拆东墙补西墙” | 逻辑链断裂 | 检查推理的每一步是否成立 |
| 因果倒置 | 把结果当原因，或原因和结果混淆 | 追问“为什么”检验因果链 |
| 自相矛盾 | 前后说法冲突 | 对比前后文同一话题的表述 |
| 循环论证 | 用结论证明前提 | 检查论证是否独立于结论 |
| 前后重复 | 同一内容多次出现 | 标记相似段落，合并或删除 |

### 起承转合要点

- **起与合**：提出一个思想观点后，阐述要合情合理，起合自然有序
- **承与转**：不仅是语言的转换过渡，还是实质内容和结构形式的承接及流转
- 起承转合是写作逻辑对结构的统领手段

## 二、结构审查

### 三个关键词

借鉴维特根斯坦结构主义：

1. **状态**：文稿文章是有序的、立体的、运动的“状态”。好文稿的结构状态都是纵横捭阖的
2. **关系**：不是积木式堆积，而是处于相互制约并变化着的关系存在。理顺关系，结构便顺当
3. **锁链**：一环紧扣一环，像化学分子式的结构链，要时刻抓住这些有机结构链往前走

### 鸟巢隐喻及其操作转化

文稿结构应该像鸟巢，大小合适、遮风挡雨、出入方便、美观实用。

**操作化审查要点**：
- **底部是否筑严实？** 文稿的基础论述、背景交代是否扎实？有没有让核心内容“掉下去”的风险？
- **整体是否椭圆形错落有致？** 各部分是否既有整体感又有局部的错落变化，而不是呆板方正？
- **是否实用好用？** 结构是否为内容服务？漂亮好看只是一方面，更重要的是实用好用耐用。

### 结构分类

| 分类方式 | 类型 A | 类型 B |
|---------|-------|-------|
| 方向 | 纵向结构，递进性 | 横向结构，板块式 |
| 可见性 | 有形结构，以标题为特征 | 无形结构，骨架深藏，脉络自然贯通 |
| 层级 | 简约结构，两三层 | 复杂结构，四五层以上 |

### 结构审查清单

- [ ] “四梁八柱”有没有歪？
- [ ] 架子是不是拉大了或“小马拉大车”？
- [ ] 门窗是不是开在了正地方？
- [ ] 各部分比重是否均衡，不畸轻畸重？
- [ ] 层级是否适当，不过多也不过少？
- [ ] 是否陷入刻板的“三大块”套路？
- [ ] 结构是否有残缺不全问题？
- [ ] 刚性与韧性是否兼顾？

### 反模式

- **死板三大块**：所有文稿都硬搞成“归纳情况、分析原因、提出建议”，不管是否适合
- **叠床架屋**：结构过于复杂烦琐
- **头绪过多**：层级眼花缭乱
- **松垮零碎**：缺乏整体感

## 三、关系模式审查

### A. 并列关系

**特点**：横向分布，内在各关系不需要特别照应。

**三个审查要点**：

1. **“切块”和“拉条”是否科学合理？** 块要切得有道理，条要便于问题研判和事情表述
2. **条块之间的“辈分”是否正确？** 各条各块应在一个水平线上，不能把爷爷辈和孙子辈混在一个等级里。本来是条条的事，不要当成块块来分列
3. **各部分比重分配是否大体相等？** 不能某块 1500 字，某块 150 字

### B. 递进关系

**特点**：纵向分布，由浅入深，由表及里，由下到上。

**审查要点**：
- 环环是否紧扣，各关系之间是否相互契合？
- 是机械的“物理递进”还是多路径多层面多方位的“化学递进”？
- 递进也可以是反向的，由深入浅、由宏观到微观，不违背写作逻辑

## 四、分类维度的选择（v9.3 新增）

> 沉淀来源：2026-07-28 中注协实战。原稿把「上云后要落实的保护措施」按**技术门类**切（平台准入与等保、数据归属与运维权限、加密访问控制与审计），客户主任读完的反应是「读不懂」。他真正要问的是「我就得评估一下这个保护措施我做不做得到」。改按**责任主体**切（服务商落实 / 云平台自带 / 本单位承担）之后，一眼就能看到「本单位新增的只有一次性一项」。

### 4.1 按受众用来做决定的维度切，不按材料的自然属性切

同一批内容有多种切法，**选哪种取决于读者拿它去干什么**，不取决于内容本身最自然的归类。

| 读者要回答的问题 | 应当选的维度 | 不该选的维度 |
|---|---|---|
| 我做不做得到 | 责任主体（谁来做） | 技术门类 |
| 要花多少钱 | 成本科目 | 实施阶段 |
| 什么时候能好 | 时间节点 | 功能模块 |
| 风险在哪 | 风险等级 / 后果 | 系统清单 |
| 选哪个方案 | 决策变量（价格、准入、可扩展性） | 厂商名录 |

**自检法**：写完一节，把读者最关心的那句问话（最好是他的原话）拿来问这一节——**答不上来 = 维度选错了**，不是内容不够。

### 4.2 用读者的原话切分和命名

客户会上说的原话，就是最好的小标题和最好的分类依据。他说「我做不做得到」，那就按「谁来做」分；他说「区别在哪」，那就按对比维度分。**换成我方的术语体系重新命名，等于把读者的问题翻译成我方的答案结构，读者要在脑子里再译一次。**

### 4.3 举重以明轻

摆同业先例时，如果最贴近的同类机构用的是**更宽松**的方案，不要回避，也不要硬说它支持我方结论——把它作为**下限证明**：连更宽松的路径同类机构都在走，我方选更严的这一档，准入门槛只高不低。

⚠️ **但下限证明必须紧跟差异说明**，否则读者的第一反应会是「跟我们最像的单位比较过，结论是没必要还更贵，那我们为什么要选贵的」。差异说明缺位 = 这段是在替反对意见说话。

### 4.4 分类三铁律

1. **互斥**：同一个对象不能同时落进两类（「（四）其他机构 /（五）私有云路线」，某机构两边都算 = 违规）。
2. **同层**：一组分类只能用一个维度（前四项按机构切、第五项按技术路线切 = 违规）。
3. **穷尽**：三类之外还有第四类而未列 = 读者会问「那剩下的呢」。
